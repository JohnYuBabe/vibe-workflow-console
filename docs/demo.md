## 三条规则在录屏里如何体现

- **规格门禁（422）**：`draft → ready`、`ready → in_progress` 要求规格 trim 后 ≥20 字、非空验收标准 ≥3 条。录屏 00:08–00:13 的 422 属于这一条，也是唯一使用 422 的分支。
- **验证门禁（409）**：`review → done` 至少要有 1 条 `result=passed` 的验证。录屏 00:13–00:19 被它拦下，错误码 `VERIFICATION_GATE`。
- **追溯门禁（409）**：`review → done` 至少要有 1 条 AI 会话，或不少于 20 字的人工记录。`登录与 JWT` 已有 1 条 AI 会话，所以这一段没有触发 `TRACEABILITY_GATE`；它和验证门禁是同一接口上的两条独立检查。
- **完成即定格**：流转成功后，规格、验收标准、人工记录、验证、AI 会话与任务删除都返回 409 `TASK_IMMUTABLE`。录屏里体现为编辑框变只读、写入口消失。

## 自己跑一遍

命令来自 README「本地启动」，按顺序执行：

```bash
cp .env.example .env
pnpm db:up
pnpm install
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Web 在 http://localhost:5173，API 在 http://localhost:3010/api。

| 账号 | 密码 | 用途 |
| --- | --- | --- |
| admin@example.com | admin123 | 7 项权限，包含 `task:write`；录屏用这个，能编辑并看到流转按钮 |
| editor@example.com | editor123 | 6 项权限，能写项目、任务、决策，没有 `user:manage` |
| viewer@example.com | viewer123 | 3 项只读权限，看不到写按钮与流转按钮 |

录屏前再跑一次 `pnpm db:seed`，把数字恢复成上面的种子值。seed 会清空全部项目，再重建项目 vibe-workflow-console；任务 id 会变，恢复后刷新页面，停在旧任务 URL 会显示「任务不存在」。

toast 只显示中文原因，不显示 422 / 409；状态码在字幕里标出。数字与文案的出处：`apps/server/prisma/seed.ts`、`packages/shared/src/task-policy.ts`、`apps/server/src/tasks/task-status.service.ts`、`apps/web/src/utils/api-error.ts`。
